# 设计

## 架构

配置与schema → 冻结manifest → 初始账户 → 目标母单 → 合法物理订单事件 → 可见交付层故障 → 独立验收与质量报告。先实现最小标准库命令行，具体语言在1.1比较团队运行环境后锁定；题库当前PowerShell构建不必强制与仿真器同语言。

生成数据放入data/generated，不入Git。observations与ground_truth物理分离，决策API只读observations。重复消息不生成第二次物理成交；ACK/成交到达顺序可变化但物理因果有效。每个故障具有唯一scenario_id与fault_schedule，未知受理保留占用，撤单请求不释放未确认额度。

初始资金与价格尺度关联，使200股买卖场景有可行与不可行两类；不是随机均匀填列。冻结股票池不按未来五日完整率静默替换。测试股票可用SYN000001等标识，manifest必须说明不是实际A股清单。

test_only规则包只支撑夹具，不声称真实T+1例外、整手、笼子和时段合规。实际规则补入后走单独证据评审。首版无需完整市场模拟，成交只是由声明的撮合假设驱动的物理事件。

## 放行

至少正常、重复回报、回报乱序、部分成交后撤单、未知受理超时、断连快照恢复、资金不足、共享限频、陈旧行情、主备双主防护10类场景。使用独立小账本与事件表作为oracle，故意破坏消息/分录必须失败；200股5日输出可重复且所有场景有明确预期。无真实校准时全部synthetic、calibration=false。
