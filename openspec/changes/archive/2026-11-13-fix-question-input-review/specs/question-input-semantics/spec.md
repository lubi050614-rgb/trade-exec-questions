## Purpose

管理题目与合成输入之间可执行的语义契约，确保故障来自给定事件、共享场景符合题意、批量标的真实存在、数值单位稳定，并将文件完整性与独立业务语义验收分开记录，防止用模板复制和人工填写结果代替验证。

## ADDED Requirements

### Requirement: 从原始输入验证故障
系统 MUST 从原始事件复算跨通道顺序和滑动窗口峰值，不得仅比较两个预填结果字段。

#### Scenario: 人工峰值一致但事件不支持
- **GIVEN** 事件时刻为0、2000、4000、6000毫秒，窗口长度1000毫秒
- **WHEN** 报告峰值仍为4
- **THEN** 校验失败，即使其他人工峰值字段也为4

### Requirement: 题意决定场景和样本
系统 SHALL 为每题记录显式场景选择；声明200股五日专用批量输入的案例 MUST 实际含200个唯一标的和五日可关联账户/请求记录。

#### Scenario: 申购失败后的残留库存
- **GIVEN** 题目关注申购失败但股票已买入
- **WHEN** 读取专用共享申赎事件
- **THEN** 返回失败场景，不因题号为Q03而返回恢复成功场景

### Requirement: 单位和验收等级明确
系统 MUST 显式声明价格单位，不由是否含小数决定单位；精确故障就绪 MUST 由节点对应的独立语义检查支持。

#### Scenario: 只有结构检查
- **GIVEN** 某节点仅通过文件、配方和人工字段关系检查
- **WHEN** 生成就绪报告
- **THEN** 记录结构已验证和语义待审，不自动宣称精确故障验收完成
